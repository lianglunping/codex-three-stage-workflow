# 审计模块

## 目录

1. 审计边界、证据清单与输入不可变性
2. 数据流与定量可追溯性
3. 基因组参考与坐标契约
4. 代码与流程可靠性
5. 跨产物一致性与语义验收
6. 方法学与结论强度
7. 可复现性
8. Release 与版本面一致性
9. 多代理 revision 与审计凭证
10. 交付完整性与总体判定

统一证据状态：

- VERIFIED：由当前可检查证据直接验证。
- INFERRED：基于现有证据的合理推断，但仍缺直接验证。
- MISSING：验收需要但当前不存在或不可访问。
- NOT_APPLICABLE：已说明理由且确实不适用。

## 模块一：审计边界、证据清单与输入不可变性

目标：冻结本次审计看到的项目状态，避免把未知材料或变化后的输入
误当作当前证据。

检查：

1. 记录审计截点、项目入口、审计范围、可用与缺失材料。
2. 建立输入 manifest：路径、类型、大小、checksum、来源、版本和用途。
3. 解析符号链接并记录实际目标。
4. 区分原始输入、工作文件、中间结果、正式结果和 release。
5. 比较运行或修订前后的 checksum，检查原始输入是否被改写。
6. 仅有 mtime 或文件存在不能证明不可变。
7. 缺少 checksum 时明确证据限制，不推定输入未变化。

## 模块二：数据流与定量可追溯性

目标：将关键数字、图表和结论追溯到明确输入和计算。

检查：

1. 绘制从数据起点到最终结果的数据流。
2. 将每个关键数字绑定生成脚本、输入集合、参数和结果字段。
3. 检查 sample universe、row universe 和 variant universe 在阶段间是否
   发生未解释变化。
4. 检查主键唯一性、join cardinality、重复计数、漏计和选择性汇报。
5. 重算样本数、变异数、分类统计和图表源数据中的核心数字。
6. 核对多级筛选集合、父子集合及其分母。
7. 识别手工修改、临时脚本、未记录步骤、孤儿文件和断链。
8. 图表必须能追溯到命名表格或明确计算。

## 模块三：基因组参考与坐标契约

仅在项目涉及序列、基因组区间、变异或注释时启用。

检查：

1. 物种、assembly/build/accession 和 reference FASTA checksum。
2. annotation source/release、checksum 及其与 assembly 的匹配。
3. contig 名称、顺序、长度和别名映射，例如 Chr1、chr1、1。
4. 多 assembly 时的转换记录、失败位点和未映射处理。
5. BED 0-based half-open 与 VCF/GFF 1-based closed 的转换。
6. 区间端点、插入缺失锚定和结构变异 END/SVLEN 约定。
7. strand、reverse-complement 和 transcript/gene model 选择规则。
8. VCF REF 是否匹配 reference FASTA，REF/ALT 方向是否被正确解释。
9. left-normalization、multiallelic splitting、symbolic allele 处理。
10. 样本、材料、世代、组织、地点、时间和批次标识是否一致。

坐标或参考契约缺失且会影响结论时至少判为 Major；已证明错配污染
核心结果时判为 Critical。

## 模块四：代码与流程可靠性

目标：验证代码、参数、失败处理和边界条件。

检查：

1. 输入 schema、参数和路径验证。
2. 读取、过滤、分组、统计、注释和导出逻辑。
3. 阈值比较符、off-by-one、缺失值、空输入和部分输出。
4. 主键、样本分类、世代/处理组和优先级逻辑。
5. 命令失败传播、错误码、断点恢复和重复运行幂等性。
6. 并发、随机性、随机种子和非确定性。
7. 硬编码路径、魔法数字和跨环境假设。
8. 输出 schema、列定义和命名是否与实现一致。
9. 进程完成或 exit code 0 是否被错误地当作语义通过。

## 模块五：跨产物一致性与语义验收

目标：确认结果内容正确，而不仅是文件存在。

检查：

1. 为关键产物定义 schema、主键、记录数、允许范围和非空约束。
2. 检查上下游样本、位点、分类和总数不变量。
3. 核对 README、方法、表格、图、报告和 release 中的数字与口径。
4. 验证图表与源表、统计与分母、文件名与内容是否对应。
5. 为 TSV/XLSX 建立明确 sheet 映射，比较列、主键、记录数和内容。
6. 区分排序差异与内容差异；规范化空值、日期、公式缓存值和浮点容差。
7. 检查 Excel 行列限制、截断、隐藏 sheet、筛选状态和长 ID 类型转换。
8. 无法证明等价时不得因肉眼相似而通过。
9. 对关键结果运行项目既定或新定义的机器可检验 semantic QA。

## 模块六：方法学与结论强度

目标：判断方法是否适用、结论是否越过证据。

检查：

1. 工具、参数和参考资源是否适合物种、数据和研究目标。
2. 阈值是否有当前数据、方法学或文献依据。
3. 统计功效、混杂因素、多重检验和独立验证。
4. 注释、变异分类和统计汇总是否合理。
5. 是否存在循环论证、选择性汇报或忽略负结果与限制。
6. 将结论分为直接支持、合理推断和证据不足。
7. 相关或共分离是否被错误提升为因果或机制。
8. 检出变异是否被错误写成诱发、遗传、因果或育种价值。
9. 参考资源或分析版本变化是否可能改变结论。

## 模块七：可复现性

目标：确认第三方能否重现主要结果或理解不能重现的原因。

检查：

1. 精确入口命令、配置、参数、输入输出映射和版本。
2. 环境、容器、lock/export、数据库和参考资源。
3. 随机种子、并行顺序和平台差异。
4. 临时或人工步骤是否留有审计记录。
5. 是否存在隐藏依赖、未记录脚本或外部文件。
6. 重跑验收是 bitwise、结构等价还是语义等价。
7. 是否有最小复现路径或完整 provenance。

## 模块八：Release 与版本面一致性

存在正式交付或发布包时启用。

检查：

1. 当前 active release 和 superseded 版本是否明确。
2. README、文件名、表头、图例、manifest 和压缩包内部版本是否一致。
3. release 是否仅包含白名单文件，是否混入旧版、临时文件或内部日志。
4. checksum manifest 是否完整并可验证。
5. 解压后是否可独立理解、使用和复核。
6. TSV/XLSX、图和报告是否来自同一冻结结果。
7. 命名修正是否覆盖全部发布面。
8. 项目要求确定性构建时，比较两次规范化构建结果。

## 模块九：多代理 revision 与审计凭证

在多代理、正式发布前或审计期间工作区可能继续变化时启用。

检查：

1. assignment registry 是否记录角色、模型、base revision、读写域、状态和
   return fingerprint。
2. 是否只有 root 作为 canonical integrator，其他 writer 是否仅写独占 staging。
3. seal 前 assignment 与 job 是否全部 terminal，两个连续 manifest 是否一致。
4. 审计是否绑定 `revision_id`、`manifest_sha256`、`scope_fingerprint` 和
   `audit_cutoff`。
5. auditor 是否只读，独立复核是否使用相同 revision 和 scope。
6. seal 后变化是否按 metadata-only、semantic、out-of-scope 或 late-write 分类。
7. semantic 或 late-write 是否使 receipt 失效并触发最小受影响链复验。
8. stale base、重叠写域、丢失 registry 更新或未静默 seal 是否被拒绝。

无法证明审计绑定当前 sealed revision 时，不得将旧 PASS 作为当前 Ready
证据。

## 模块十：交付完整性与总体判定

先根据用户承诺和用途定义 delivery profile，再判断缺失项。不要机械要求
所有项目都必须具有同一目录结构。

检查：

1. 必要代码、配置、结果、说明、方法、字段字典和复现证据。
2. 输出目录是否区分工作结果、正式结果、release 和归档。
3. 是否存在唯一活动版本和可追溯旧版本。
4. 内部 QA 证据是否与对外交付内容分离。
5. 严重度是否基于对科学结论、数据完整性、复现或发布的影响。

建议判定：

- Critical：污染核心结论、破坏输入/证据、阻塞复现或导致错误发布。
- Major：重要结果或交付口径不可靠，但影响可定位和修复。
- Minor：不改变主要结论的局部不一致或说明缺口。
- Suggestion：改进建议，不作为当前验收失败。
