# Project workflow example

## 复杂任务三阶段工作流

只有明确调用 `$three-stage-complex-workflow`、对具体任务提出“自动完成三阶段工作流”
“自动推进3阶段工作流”等要求，或续接任务匹配且状态为 `ACTIVE` 的可验证运行时，
才启用专用工作流。复杂、多文件和工作流维护本身不自动激活。

- 新任务依次经过 `【分析问题】`、`【细化方案】`、`【执行方案】`。
- 分析必须详述恰好 3 个有实质差异的方案，再给出比较和推荐；细化逐文件明确
  变更、接口、验收和失败处理，不能直接跳到执行。
- `MANUAL` 每次只推进一个阶段，等待方案选择和实施批准；明确授权的
  `BOUNDED_AUTO` 可在 `authority_envelope` 内自动推进，但仍展示三个详细方案。
- 记录 `task_id`、`current_task_id`、阶段、模式、`approval_evidence`、
  `scope_fingerprint`、结构化验收门、转换回执和修复预算。续接时任务必须匹配，
  不推断补齐授权，已关闭任务不自动重开。
- 新记录使用 `workflow_policy_version: "2.1.0"` 和 `model_routing`。
  默认 Astra 分析/细化、Sol 执行；记录实际模型身份、运行时可用性和任务能力证据。
  用户明确指定模型时记录覆盖依据；模型不可用或缺少委派授权时暂停，不静默替换。
- Analyze 和 Refine 保持只读；root 是唯一 canonical integrator，最多一个活跃写入者。
  子代理模型无固定白名单，但必须有独立的可用性、能力与委派授权证据。
- 自动推进不授予子代理、插件、外发、提交或推送权限。专用 Skill 不得绕过三阶段批准边界。
- 新自动运行默认允许修复周期续期：同一问题 3 次或当期 6 次后，记录诊断、下一方法
  及进展或新证据，保留累计历史。旧记录保留原固定预算语义；无新证据或方法不得重复重试。
- 输入、范围或授权实质变化时返回受影响的规划阶段；原始数据覆盖、不可逆操作、
  凭证/全局环境变更、科学证据冲突或必需验收无法核验时停止相关行动。
- 复用仍适用的证据，只运行受影响的检查；交付物及必需验收均完成后才关闭运行。
