# 本机科研工作流（Codex / DeepSeek Harness）

## 接到新任务

首次回复仅根据用户消息，用自己的话简短复述目标、预期交付物、关键约束，说明建议直接做还是调查后做，以及影响判断的一个理由。等待用户确认，或接受纠正并复述修正之处，再开始查阅、调用工具或动手；不得先枚举或读取任务文件，再补做首次复述。会话启动规定的例行检查及读取工作流规则除外。确认用于确定任务范围与候选稿内容，不能由操作可逆或一般执行授权代替。同一任务的确认、补充和进度询问沿用已确认的范围；用户明确要求略过某个确认点时，按其指定的范围推进。

目标和基线唯一、改动可逆、验收明确且不改变科学口径时，首次确认后直接执行并验收。例如只改指定图的轴标题，同时导出 PDF 和 PNG。会改变样本、分母、参考、统计单位、结论，或涉及多个候选版本的整合、可能丢失成果、重要取舍时，进入下面三个阶段。多个版本的整合不因 README 已指定正式入口、改动可逆或暂未见冲突而跳过调查和第二次确认。途中发现上述情况就转入调查。普通交谈和同一任务的追问自然回答。

## 三阶段

1. **调查现状。** 从当前项目的入口、已确认正式版和相关证据查起。按需查看同目录的 RESOURCE_INDEX.md 所列文档和专长，只读与问题直接相关的部分。查清原始目标、哪些已完成、旧版有哪些独有结果、哪些应保留。材料或表达不完整时先查现有文件；仍有歧义时，提出最影响决定的一个问题，说清不同答案的后果。能独立完成的部分继续。调查结束向用户复述经证据校正的需求，具体列出每版独有结果及其拟保留位置、边界、影响判断的缺口和拟验收的结果，等待第二次确认。不得以“全自主”笼统代替用户指定的两次确认，除非用户明确免除该次等待。
2. **设计方案。** 按已确认的范围选最简单可行的方法和相称的验证。只比较会产生实质差异的可行方案。第二次确认覆盖的范围内，设计完成即可执行。需改变科学目标、写入范围或执行不可逆操作时，再确认相应决定。
3. **执行与验收。** 从确认的基线实施，按原始目的和上版逐项核对数据、子图、结论和复现入口。子图合并、移位、删除时说明原结果的去向与原因。发现有价值的中间结果，在正式 README 简记证据位置、适用范围和是否待验证。发现触及新课题时可记录，保持当前任务的范围。

## 绘图和分析目录

科研绘图及改图（包括标题、标签或重新导出）在首次确认后先读取本宿主的 academic-figure-skill，再按其入口读取 bio-publication-figure-director；按任务选择模式，导出技能不能替代总控。局部改图只修改授权元素，沿用已有绘图体系、输入、尺寸与样式；采用轻量合同和与修改相称的实际成图验收，不额外建立整套图件框架。 技能路径以本策略所在配置目录的同级 `skills/` 为准（Codex 默认 `~/.codex/skills/`，DeepSeek Harness 默认 `~/.dsh/skills/`）；不搬用其他宿主的模型路由、权限或插件。

每张图或每项独立分析一个正式目录，保持现有编号和入口。子图用稳定的面板标识；因论文编排改号时，在 README 中记录能追溯结果的对应关系。在已有导航中更新一条指向这个目录的链接。多个旧版本并存时对照脚本、输入、输出和独有内容；时间戳或最大版本号不足以确立正式版。

正式目录只收五类内容：代码、实际输入、正式输出、供助手复现的 README.md、供用户阅读的 HTML。可容纳多份文件。大体积、受控或共享的原始输入在 README 登记可核对的来源、版本与定位方式；保留实际用于绘图的小数据表。其他文件型分析按实际目的组织这五类；单份译稿、已有文档的局部修订等依用户指定的交付物办理。

绘图优先选项目现用的 R 或 Python，使用简洁脚本和解释关键判断的中文注释，同一图输出矢量 PDF 和高分辨率 PNG。代码开头、README、HTML 各自交代背景、需求、方法和关键代码的作用。README 给出准确文件名、运行入口、输入输出、关键参数、依赖版本和适用的种子。HTML 先给出图或结果及它怎样回答问题，再按需解释方法。代码头说明当前实现，删去已失效的版本说明。

修订在当前任务目录的 temp/ 中准备，保留现有正式版。第二次确认如“可以，按这个方向改”只授权准备候选稿；完成后展示可审阅文件并等待定稿，不能将方向确认视作定稿。用户看过候选稿并明确回复“确认定稿”或同义确认后，整合已经通过的内容，核对正式路径能复现、HTML 引用有效、PDF 与 PNG 内容一致、旧版独有成果有交代。保留可恢复的原件直至验证通过。只清理本轮拥有的临时内容；temp/ 清空后移除。遇到不明文件、其他任务文件或唯一证据先查明归属。历史归档、冻结数据和其他项目目录另行授权处理。
